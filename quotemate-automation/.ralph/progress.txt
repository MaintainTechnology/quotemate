## Learnings
- tenants.status was in SELECT_COLS + logged since v6 but never gated anywhere;
  the gate belongs BEFORE customer creation (step 2a) so suspended tenants
  create no rows at all.
- lib/customers/lookup.ts creates a supabase client at MODULE level — pure
  helpers must live in sibling pure modules (memory-scope.ts) or their tests
  need env. Same trap as twilio.ts (env read inside fns, so that one's safe).
- customers.phone_number is GLOBALLY unique (mig 008); tenant_id is a
  first-writer-wins stamp, not a partition key. App-layer memory scoping at
  the single resolution point in the route covers every downstream read;
  the composite-key migration remains Phase-2.
- trade-scope.test.ts pins tradeScopeDirective byte-for-byte with inline
  snapshots ("Phase 0 exit gate"). Deliberate directive changes must update
  the pins AND the header comment, or the intent is lost.
- The advertise half of US-005 (extraTradeLines, roofing-only branch) had
  already landed in 48a1e9d6 the same day — always re-read dialog.ts before
  extending it; this session had three concurrent editors.
- WhatsApp senders are never tenant long codes: sendWhatsApp always uses
  TWILIO_WHATSAPP_FROM, so the only safe fallback scope is platform-number
  flows (whatsappFallbackAllowed).
- Twilio treats ONLY whole-message keywords as opt-outs and then blocks
  sends (21610) — so global STOP handling is silence+close, and phrase-level
  "cancel the booking" must still reach the dialog.
- asQuoteTierMode(null) → 'single' is THE platform default; any surface
  hardcoding 'good_better_best' as a fallback is a mismatch bug.
- Roofing measure-path park at await_booking now KEEPS pending_quote_token
  (needed by the booking-confirm tradie notify link). nextRoofingConversation-
  State's 'inspection' arm still nulls it — route persists explicitly, so
  only the route's own persists matter there.
