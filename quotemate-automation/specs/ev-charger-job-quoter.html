EV Charger Quoting

Make an EV charger enquiry a first-class, demo-able job on the dashboard quoter: ask the qualifying questions a sparky actually needs, propose a grounded Good/Better/Best price that includes the charger unit when the tradie supplies it, and hand off to the existing $99 site-visit booking funnel. Tesla and BYD are the worked examples.

Jon's brief: "a customer requests a new EV charger for their car — maybe try Tesla and BYD — it should ask the questions, then propose the price, then allow them to book."

What already exists

The plumbing is live — the content is thin. This spec closes the gap without rebuilding anything.

Job type

ev_charger is first-class across the intake enum, the dashboard form, the SMS extractor and the grounding validator — but the form asks only two questions (location + phase).

Assembly

One shared row, "Install EV charger": $120 ex-GST sundries + 3.0h labour, single-phase 7 kW, charger unit excluded. Toggled OFF for every electrical tenant.

Pricing data

Zero charger products anywhere. No Tesla, no BYD, no brand registry, no sanity bounds row. 0 of 241 historical intakes mention a charger — genuinely new in prod.

Booking

The funnel needs nothing EV-specific: quote SMS → /q/[token] → flat $99 refundable site visit → calendar → confirmation texts. Prices display; the $99 is the only charge.

Requirements

R1

Five qualifying questions code

Replace the two-field ev_charger entry in lib/quote/job-fields.ts. Option strings land verbatim in the transcript — they are the model's contract.

  1. What car is the charger for? Tesla · BYD · another EV · not sure
  2. Who supplies the charger unit? customer already has it · we supply it · not sure
  3. Where is the charger going? free text — garage, carport, external wall
  4. Roughly how far is the switchboard from the charger spot? under 5 m · 5–10 m · over 10 m · not sure
  5. Single phase or three phase? unchanged — three phase routes to the site visit

Hard rule: no new field code may collide with RECIPE_SLOT_CODES — those are filtered out of the transcript and the answer silently vanishes (this field's own bug history). Extend the guard tests.

R2

Deterministic three-phase gate code

Today "three phase → inspection" is a prompt rule only. Stamp inspection_required = true in /api/tenant/job-quote when the three-phase option is picked, so routing never depends on model discretion.

R3

Stock the charger products data

Demo tenant stocks two active catalogue rows in category ev_charger with Jon-confirmed prices: a Tesla Wall Connector (7 kW) and a BYD-compatible Type 2 wallbox. The form's existing product picker surfaces them automatically and pins the choice into the quote. No invented prices in shared data — the pricing book is built with the tradie.

R4

Flip the service toggle data

"Install EV charger" → enabled in the demo tenant's Services tab. The dashboard prices regardless, but the toggle governs the SMS path and keeps the pipeline coherent.

R5

Fix the contradictory copy code

The Services tab still lists "EV charger install" as inspection-only. Remove it from ELECTRICAL_INSPECTION_ONLY so the UI stops contradicting the tool.

R6

Sanity bounds code

New migration seeding a job_type_bounds row for ev_charger — drafted at max 10 labour hours, $400–$6,000 total ex-GST, provisional pending Jon. Today an absurd EV total sails through unbounded.

R7

Priced draft, held for review

Tesla + single phase + pinned Wall Connector → non-null G/B/B grounded on the install assembly plus the charger-unit line when the tradie supplies it; install-only when the customer does. Dashboard drafts always hold for tradie review before sending — by design, and it demos well.

R8

Booking — verify, don't build

Confirm & Send → customer SMS → quote page with prices + the single $99 CTA → Stripe (test mode) → calendar → thanks page, with both confirmation texts. Verify the demo tenant has booking windows and an owner mobile set.

Demo prerequisites — config only, no deploy

  • Toggle the EV service on in the demo tenant's Services tab (R4).
  • Stock the two chargers in the tenant catalogue with Jon's prices (R3).
  • Check booking windows and the tenant's owner mobile — a held quote with no mobile notifies nobody.
  • Stripe test card ready (4242 4242 4242 4242) — payments are test mode.
  • Answer "single phase" in the walkthrough to stay on the priced path; three phase correctly detours to the $99 visit.

Edge cases

Three phase selected
Deterministic inspection quote — tiers nulled, $99-only. Expected, not a failure.
"We supply" but no product pinned
Nothing grounded to price the unit against — validator may downgrade to inspection. Demo always pins a product.
Distance over 10 m
Model may scope extra labour (grounds against the book rate); invented material lines downgrade to $99. Demo uses under 5 m.
Customer-supplied unknown charger
Install-only quote; the assembly's exclusions already cover the unit.
Property has solar
Existing load-assessment risk flag already fires for EV work. Leave as is.
Absurd model total
Caught by the new R6 bounds → inspection route, visible at tradie review, never sent silently.

Definition of done

Open questions for Jon

  1. Charger prices — supply cost + sell price for the Tesla Wall Connector and a BYD-compatible unit. R3 blocks on this; we don't invent prices.
  2. Supply model — does he normally supply the unit, or does the customer buy it? Sets the default answer order.
  3. Three phase — keep it inspection-only, or build a priced three-phase path later?
  4. Labour — is 3.0 h + $120 sundries right for a clean single-phase install, and are 10 h / $400–$6,000 sane bounds?
  5. Demo tenant — Sparky ($110/h) or Atomic Electrical ($120/h + $350 call-out minimum)? The book rate changes the demo numbers.
  6. Distance pricing — confirm cable-run cost on the $99 visit for now (default), or make distance move the quoted price deterministically (a bigger phase-2 job)?
