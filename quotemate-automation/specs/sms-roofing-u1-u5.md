# Roofing/SMS receptionist — U1–U5, the unresolved defects deferred from prior passes

## Title
Close the data-integrity, wrong-parcel, inspection-framing, burst-determinism and self-correction gaps the audits left open (U1–U5), each with a root-cause fix, unit tests, and a live scenario-runner gate where the failure is timing-bound.

## Goal
A tenant's intake never overwrites another tenant's customer row (U1); a confirmed address is never measured against a neighbour parcel (U2); an inspection-routed roof never shows a firm total or a mismatched structure count (U3); a burst that contains the address always harvests it (U4); "no wait yes" at confirm_address confirms (U5c). Why: the audits proved each is live-reachable, and the money/trust paths must be correct before real customer volume.

## Role
Principal engineer. The roofing gather + compose + intake are PURE, unit-tested modules; the routes only wire them. Customer memory is phone-keyed and globally shared, so every write is a potential cross-tenant write. Money path tool-call-only; no em dashes in customer SMS; AU/NZ formatting. Verification is a NET, not a gate — a map/Geoscape outage or a missing tenant must never block a lead or a write.

## Context (grounded in code opened)

The pure predicate already exists: `customerMemoryAllowed(customerTenantId, tenantId)` (`lib/customers/memory-scope.ts:18`) — blocks only when BOTH sides are known and differ; the READ side already uses it (`route.ts:1128`). Reuse it on the WRITE side.
- **U2** — `lib/roofing/providers/geoscape.ts`. `resolveAddressId` (:217) takes `pickAddressId(res.body)` (:554), the top-1 fuzzy match, with no street-number check — Geoscape's `/addresses` is a scoreless fuzzy top-1 (a postcode digit out silently returns a different house). The identical money-path guard already exists at `lib/sms/verify-address.ts:120-124` (`firstStreetNumber` disagreement ⇒ refuse). The Geoscape response element carries the matched address string (`first.address`/`first.formattedAddress`, seen at `verify-address.ts:216-223`). `failure('address_not_resolved', …)` already routes the measure caller to the safe inspection fallback.
- **U3** — `lib/sms/roofing-compose.ts`. `buildRoofingReplyMessage` (:181) picks `composeInspectionMessage` vs `composeEstimateMessage` on `isInspectionOnlyQuote` (:198) — a **per-structure** predicate. A job routed `inspection_required` at the JOB level (unknown intent) that still has one quotable structure returns `false` ⇒ firm `composeEstimateMessage` with `quotableCount = structures - flagged` (the live S7 "2 structures, $159,885" while the measurement row was structs:3 / inspection_required). `narrowQuoteToStructures` (:304) sets job `routing.decision` to `inspection_required` only when the primary needs inspection or nothing is quotable — so a genuine mixed job (quotable primary + flagged shed) is `tradie_review`, NOT `inspection_required`, and keeps its firm secondaries. The route keys its persisted step on the SAME predicate (`route.ts:710` `isInspectionOnlyQuote` ⇒ `await_booking` vs `quoted`, and gates the `quote_sent` notify) — message and state must move together (`route.ts:700-725`).
- **U4** — `app/api/sms/inbound/route.ts`. `handleRoofingTurn` (:1900) receives the authoritative post-debounce `turns` (:1817); `roofingTurnInput` (`roofing-receptionist.ts:452`) → `latestInboundBurst` (:429) already coalesce the whole burst on a cold start, so the address is harvested whenever `turns` contains it. The only non-determinism is whether the debounce window (`adaptiveDebounceMs` :1794, base 1500ms) captured every burst line before the leader read — a webhook-arrival/leader-election race (the documented 60s inflight-lock debt), not the pure logic.
- **U5c** — `lib/sms/roofing-intake.ts:452`. confirm_address uses `isAffirmative(msg) && !isNegative(msg)`; "no wait yes" matches BOTH `AFFIRM` and `DENY` (:309-310) ⇒ falls to the `isNegative` branch ⇒ clears the address and re-asks. `shouldBailToDialog` (`roofing-receptionist.ts:356-360`) already keeps "no wait yes" IN the roofing flow (B3, prior pass); this is the confirm refinement on top.

## Task (most important first)
1. **U1** — add an optional `tenantId` to `updateCustomerFromIntake` and `writeCustomerCorrections`; before writing, consult `customerMemoryAllowed(rowTenantId, tenantId)` and skip+log when it returns false. `updateCustomerFromIntake` already fetches the row (`cust.tenant_id`); `writeCustomerCorrections` does a lightweight `select('tenant_id')` first. Pass `tenantId` at both call sites (`structure/route.ts:523`, `sms/inbound/route.ts:2179`). A NULL row tenant or NULL current tenant still writes (heal/legacy) — only a known-mismatch is blocked.
2. **U2** — in `geoscape.ts` add pure `pickAddressLabel(body)` (mirrors `pickAddressId` envelope-walking, returns the matched address string) and `parcelNumberMismatch(requested, matched)` (first-number disagreement, both present). In `resolveAddressId`, after resolving the id, refuse with `failure('address_not_resolved', …)` when `parcelNumberMismatch(input.address, pickAddressLabel(res.body))` — never when either number is absent (net, not gate).
3. **U3** — export `shouldSendRoofInspectionMessage(quote)` = `quote.routing?.decision === 'inspection_required' || isInspectionOnlyQuote(quote)`; use it in `buildRoofingReplyMessage` and at `route.ts:710` in place of `isInspectionOnlyQuote` for step-keying + the notify gate. Keep `isInspectionOnlyQuote` exported.
4. **U5c** — DEFERRED (attempted, reverted). "no wait yes" should confirm, but three independent adversarial reviews each proved that every minimal regex heuristic (last-signal-wins, negation-span exclusion, strong-affirm-flip) false-CONFIRMS a real rejection on the wrong-roof money path: a negated weak affirm ("no that isn't correct") or a trailing agreement tag ("that's wrong, yeah") is indistinguishable from a genuine flip ("no wait yes") by token position alone. confirm_address keeps the proven-safe baseline (`isAffirmative && !isNegative`); "no wait yes" safely re-asks. A correct fix needs an intent classifier, not a regex — logged, not shipped. The pre-existing false-confirms this surfaced ("that isn't right", "not quite right", "not sure", the "no worries" idiom) predate this work and are the same larger deferral.
5. **U4** — add a unit test pinning `roofingTurnInput`/`latestInboundBurst` harvest the address from a 3-line cold-start burst in any order (pure determinism). No production change to the debounce contract. Prove end-to-end with the live S4/S11 gate; if it flakes, the residual cause is the webhook/leader race (60s-lock debt) — log it, don't rewrite the 13-test debounce.
6. **U5a/U5b** — LOG with rationale, no code: (a) wiring `verify-address` into the LLM electrical/plumbing dialog is non-minimal and low-stakes (those trades don't measure a roof); (b) idle context bleed needs transcript scoping, not a minimal change. Both recorded here, deferred by design.

The write sinks skip when the predicate is false (verified by the live two-tenant check). Live: tenant A intake after a tenant-B row for the same phone leaves B's name/suburb intact.

Live: an ambiguous address whose top-1 parcel number differs dead-ends at inspection, never measures.
- **U3**: unit — a quote with `routing.decision==='inspection_required'` and a quotable structure ⇒ `buildRoofingReplyMessage` returns the inspection message (contains "confirmed on site" / no bare firm headline) and `shouldSendRoofInspectionMessage===true`; a `tradie_review` mixed job still returns the firm estimate. - **U5c**: unit — `lastYesNoSignal('no wait yes')==='yes'`, `('yes actually no')==='no'`, `('yes')==='yes'`, `('no')==='no'`, `('maybe')===null`; `applyRoofingAnswer(slots,'confirm_address','no wait yes').address_confirmed===true`. Live: S12 confirms the address.
