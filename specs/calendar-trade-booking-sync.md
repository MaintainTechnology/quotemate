# Calendar shows every booked visit; job lists and date labels stay in sync

## Goal

Every booked site visit and paid inspection a tenant owns — including roofing/painting visits stored in `roofing_measurements`/`painting_measurements` — appears in the dashboard Calendar tab on its scheduled day, and a just-created trade job appears in the dashboard job lists within one tab-switch. Why: Jon booked a roofing inspection, the system said "it's booked", and his calendar showed nothing — the booking landed in a table the calendar never reads.

## Role

Principal engineer for this repo. Reason before acting; act with tools; minimal diffs matching the style of each touched file; parallel independent tool calls; never guess a parameter — read the file or run the check first. This spec is the contract for /build and /review — do not re-engineer it mid-run.

## Context (every claim verified against code on 2026-07-08)

Jon's five reported issues map to three code-verified defects:

- **RC1 — trade bookings are calendar-invisible (Issues A, C, E).** `GET /api/tenant/calendar` (`quotemate-automation/app/api/tenant/calendar/route.ts`) builds `events` (`:126-134`, quotes with `scheduled_at` in window), `toSchedule` (`:143-151`, quotes paid + unscheduled) and `awaitingBooking` (`:162-171`) **exclusively from the `quotes` table**. But roofing/painting visits book via `POST /api/q/book/[trade]/[token]` which writes `scheduled_at` + `scheduled_window` to `roofing_measurements`/`painting_measurements` (`app/api/q/book/[trade]/[token]/route.ts:98-101`, table map `lib/quote/trade-booking.ts:15-18`, columns from migrations 165 + 167). Their $99 deposits land on the same tables (`paid_at`, mig 165). So a booked or paid roofing/painting visit can never appear in the Calendar tab, its "Paid · needs a time" list, or anywhere else in the tradie dashboard — the only surface showing it is the customer's own `/q/roof/[token]` page (`app/q/roof/[token]/page.tsx:667-691`). Jon's "calendar broken after UI update" (Issue E) is this data gap: `CalendarTab.tsx` renders fine but receives no rows for these bookings.
- **RC2 — trade jobs are quotes-list-invisible and the dashboard never refetches (Issue B).** Dashboard quote data is fetched once on mount from `/api/tenant/me` (`app/dashboard/page.tsx:610-631`); no refetch on tab-switch or window focus. Roofing jobs saved from the dashboard insert into `roofing_measurements` (`app/api/roofing/save/route.ts:150-188`), not `quotes`, so the per-trade "roofing quotes" filter (`page.tsx:7899-7901`, client-side on joined `intake.trade`) never shows them; they surface only via `SavedJobsSection` (fed by `GET /api/tenant/trade-jobs`), which the cross-trade workspace Quotes view does not render (`page.tsx:7906` + `:8159-8161` gate it on `tradeFilter`). This is already specced as **Tasks 2 and 5 of `quotemate-automation/specs/quotes-tab-sync.md`** (authored 2026-07-08; its Task 1 — the 100-quote cap — is already implemented at `app/api/tenant/me/route.ts:177`; Tasks 2–5 are not built). This spec inlines exactly that Issue-B slice; the aircon work (its Tasks 3–4) stays owned by that spec.
- **RC3 — booking echoes are hardcoded to Sydney while slot generation is tenant-timezone-correct (Issue D).** Slot/window generation and picker labels use the tenant's state timezone (`lib/quote/availability.ts:45-60` `STATE_TIMEZONES`/`tzForState`; `lib/quote/trade-booking.ts:48` passes `tzForState(t.state)`; `SlotPicker.tsx` renders server labels only). But the confirmation surfaces hardcode `Australia/Sydney`: `formatVisitSlot` (`lib/quote/trade-booking.ts:72-89`, renders "Your site visit is booked for …"), `fmtSlotShort` → `buildBookingConfirmationSms` (`lib/sms/templates.ts:564-597`, the booking-confirmation SMS), and the whole Calendar tab day-grouping (`app/dashboard/_components/CalendarTab.tsx:43` `const TZ = 'Australia/Sydney'`). For QLD/SA/NT/WA tenants the echoed time is 0.5–3 h off and a WA evening slot can echo as the **next day**. Jon's exact "picked Friday July 9, confirmed July 8" could not be reproduced in code for an east-coast tenant; the closest confirmed behaviours are this echo-timezone class plus the "Paid · needs a time" row showing `paid <date>` (the payment date, i.e. "today") with `time="—"` (`CalendarTab.tsx:617-647`) — easily read as the visit date. Fixing RC1 puts the booked visit on its real day, and the timezone threading plus the day-consistency regression tests below pin the whole chain.

Environment facts: gates are `npm test` (vitest) and `npm run typecheck` (**there is no `check` script**), e2e is `npm run test:e2e` (Playwright, unauthenticated pages only — no Clerk storage-state). Route tests mock supabase-js with a vi.hoisted chainable builder (`app/api/tenant/calendar/route.test.ts:10-40`). Uncommitted in-progress work exists in `app/dashboard/quote/[token]/*` and `lib/quote/report-adapters/*` (block-doc editor gating) plus a one-line mock fix in `app/api/tenant/calendar/route.test.ts:111` — build on top of it; never revert it. ## Task

1. **Calendar reads the trade-visit tables (fixes Issues A, C, E).** In `GET /api/tenant/calendar`, additionally query `roofing_measurements` and `painting_measurements` (tenant-scoped `.eq('tenant_id', …)`), each wrapped in a per-table try/catch degrade (pattern: `app/api/tenant/trade-jobs/route.ts:64-90`) so a missing table/column never 500s the calendar:
   - rows with `scheduled_at` in the `[from, to]` window → merged into `events`, sorted with the quotes events by `scheduledAt` ascending;
   - rows with `paid_at` NOT NULL and `scheduled_at` IS NULL (paid within the existing 180-day `TO_SCHEDULE_LOOKBACK_DAYS`) → merged into `toSchedule`.
   Map each row to the existing `CalendarEvent` shape: `quoteId` = row id, `shareToken` = null, new optional field `href` = `/q/roof/<public_token>` or `/q/paint/<public_token>`, `needsInspection` = true, `paid`/`paidAt`/`paidTier` from the row, `customerName`/`customerPhone`/`address` from the row's columns, `jobType` = `'roofing'` / `'painting'`, `bookingState`/`status`/`suburb`/`source` = null. Select only columns that exist on those tables (`id, public_token, tenant_id, scheduled_at, scheduled_window, paid_at, paid_tier, customer_name, customer_phone, address` — verified against migrations 165/167 and `app/api/roofing/save/route.ts:150-188`).
2. **Calendar tab opens trade rows.** Add `href?: string | null` to the client `CalendarEvent` type in `CalendarTab.tsx`; `AgendaRow` opens `href` when present, else the existing `/q/<shareToken>`. No other UI change.
3. **Thread the tenant timezone through the echo surfaces (fixes Issue D's confirmed defect).**
   - `formatVisitSlot(iso, window, timeZone?)` — optional param, default `'Australia/Sydney'`. The roof and paint quote pages pass `tzForState(<tenant state>)` (extend their existing tenant read to include `state` if not already selected).
   - `fmtSlotShort(iso, timeZone?)` and `buildBookingConfirmationSms({ …, timeZone? })` — same treatment; `POST /api/q/book/[trade]/[token]` passes the tenant's timezone (extend its `tenants` select at `route.ts:113-117` to include `state`).
   - `GET /api/tenant/calendar` returns `tenantTz: tzForState(tenant.state)` (extend the tenant lookup if `tenantFromBearer` doesn't already carry `state`); `CalendarTab` uses it in place of the `TZ` constant for `dayKey`/`todayKey`/`timeLabel`/`shortDate`, falling back to `'Australia/Sydney'` when absent.
