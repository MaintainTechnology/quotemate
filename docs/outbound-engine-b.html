00 · The build, decided

Thin glue over four services — not a second product

The correct Approach B is deliberately small: Supabase holds the truth, Inngest runs the jobs, Smartlead sends the mail, and the dashboard is thin glue with one-click actions. Every feature beyond that has to justify itself against "Smartlead already does this". The data-layer verdicts from Approach A carry over unchanged — what's new here is the machinery that replaces n8n, re-ordered for free tiers.

Application
Separate Next.js app + dedicated Supabase project, Clerk-gated

Never bolted into quotemate-automation — a lead-gen deploy must not risk the revenue app, and mixing scraped-lead PII with tenant data pollutes both the repo and the compliance story. Auth is day-one: reuse the Clerk licence with a single-admin allowlist, no public signup. A scraped-contact database behind half-finished auth is a Privacy Act breach waiting to happen.

Job engine
Inngest — Hobby tier, US$0 (50,000 step-executions/mo)

The n8n replacement: durable step functions that run inside your own Vercel functions, with retries, per-provider throttling, idempotency keys, cron triggers, free sleeps while you pace rate-limited APIs, and a run dashboard with replay — everything you'd otherwise hand-build. TypeScript-first. Fallback if the 50k quota binds: pg_cron + pgmq on the Supabase you already run, feeding a Graphile Worker on Railway (~US$5/mo). Ruled out: Trigger.dev (bills wall-clock — a job pacing against rate limits burns credit doing nothing), Upstash QStash (~500–1,000 messages/day free cap), BullMQ + Redis (standing ops for nothing Postgres can't do), Vercel Queues/Workflows (newest, least mature, meters exactly what this workload does most).

Sending
Smartlead Pro driven via its REST API — same vendor as Approach A

The custom-CRM-on-Smartlead pattern is standard (Smartlead markets its API for exactly this): the CRM creates campaigns, bulk-adds leads (~100 per call), pauses, and consumes reply/bounce/unsubscribe webhooks — while Smartlead handles warmup, rotation and ramp-up through your own OAuth-connected Gmail inboxes. Raw Gmail API for cold volume stays ruled out: sensitive-scope OAuth verification, no warmup or rotation, Workspace ToS suspension risk — you'd rebuild Smartlead's hardest features badly. Gmail API is for 1:1 replies only.

Data layer
Same waterfall as Approach A — re-ordered for free tiers

ABN Lookup (free) → Firecrawl + Claude → email finders → MillionVerifier → ZeroBounce. One material change at US$0: Prospeo replaces Hunter as the finder — Hunter's free plan has no API access at all, while Prospeo gives 75 verified emails/month with API, recurring. Hunter returns as the paid primary (~US$34/mo Starter) once volume justifies it. Apollo stays a manual browser tool for the commercial slice (its free plan was gutted in late 2025: ~100 credits/mo, no API); Clay's free tier is evaluation-only — use it once to benchmark your waterfall's match rates, then drop it.

Export
Google Sheets API — batched writes, US$0

Free with per-minute quotas (60 requests/min/user — use batchUpdate, never row-at-a-time). Airtable is out entirely for this build: its free plan caps the API at 1,000 calls per month — a single pilot sync burns the quota — and Supabase already is the CRM store. One-click export produces a Sheet; nothing else is needed.

Observability
Inngest dashboard + Sentry Developer (free) + Axiom (free, 500 GB/mo)

Inngest's run view with replay is the de facto dead-letter queue; Sentry catches exceptions and watches the pipeline heartbeat (1 free cron monitor); Axiom ingests every API call, webhook and send event as structured logs — which doubles as the queryable Spam Act evidence trail. New observability spend at launch: US$0.

One writer rule

Never run both against one database

If any n8n workflow exists, exactly one system owns lead status and the suppression table at any time. Two writers on the same tables is a double-send incident waiting to happen. Cleanest: B replaces A entirely before the first campaign, or A ships first and B imports once.

02 · End-to-end architecture

Five layers, one truth table, one gate

Supabase is the single source of truth; Inngest is the muscle; the dashboard is a thin, Clerk-gated face. Every provider sits behind a swappable connector interface — the research itself proves why: Hunter's free API vanished, Apollo was gutted, Firecrawl's credit terms are ambiguous. Provider churn is a certainty; hard-wired calls make each churn event a rewrite.

04 · Flow — enrichment & verification

The waterfall, budget-aware and free-tier first

Identical logic to Approach A with one upgrade n8n couldn't give you: a provider_budgets table tracks every remaining free credit (Prospeo 75/mo, ZeroBounce 100/mo, Apify's US$5, MillionVerifier's one-time pool) and paid spend caps. When a pool is empty the waterfall degrades gracefully — skip to the next rung or park the lead — instead of erroring mid-batch. Inngest paces requests; it doesn't know a monthly credit pool is dry. 05 · Flow — campaigns & outreach

The CRM drives Smartlead; Smartlead drives your inboxes

Two hard constraints shape this flow. Smartlead's API has one global limit — 60 requests/min per key — so every call funnels through a single throttled Inngest function using the bulk endpoint (~100 leads per call); naive per-lead POSTs 429 on the first real batch. And there is no sandbox anywhere in the send path — Smartlead has no test mode — so the pipeline carries an explicit dry-run flag that runs everything and stops at the push.

Flow — campaign lifecycle
Campaign manager

09 · What building it really costs

The bill is paid in founder hours

Read before committing

  1. Opportunity cost is the dominant risk. Every hour on the CRM comes out of QuoteMax — which currently carries live money-path debt (the $0-confirmed-solar-quote bug, token-route payment holes). Fixing those buys more revenue than any dashboard. Budget the MVP honestly: 3–6 weeks part-time, and the dashboard, auth, dedupe and dry-run story are half of it. Anything quoted under two weeks is ignoring them.
  2. Compliance liability moves into your code. The Spam Act suppression gate becomes a path you wrote: one race between an unsubscribe webhook and a queued push is an unlawful send with real ACMA penalty exposure — and no vendor to share the blame. The gate lives in SQL, suppression is checked at push time, and every send is evidence-logged.
  3. There is no sandbox. Smartlead has no test mode; every development mistake can push real leads into a real campaign spending real credits. The dry-run flag, seed data and the Inngest dev-server + tunnel setup are week-one work, not polish.
  4. Free-tier churn is now your pager. The stack stitches 10+ free tiers that demonstrably change without notice — Apollo gutted in 2025, Hunter's free API removed, Apify's actor-pricing migration already scheduled for October 2026. The connector interface and provider_budgets table exist precisely so each churn event is a config change, not a rewrite. Steady-state maintenance: 2–5 hours/week.

Watch the Inngest cliff: functions PAUSE silently at the 50k monthly quota — set a usage alert well before it, and alert on every provider's 402/429 responses so quota exhaustion surfaces as a page, not as a week of quietly empty enrichment. Scope creep is the other trap: sequencing editors, unified inboxes and enrichment marketplaces already exist inside Smartlead — the correct build stays thin glue.
