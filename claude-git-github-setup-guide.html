Connect Claude to your code

Three tools, one setup. By the end of this guide, Claude can read your project, make changes for you, and save those changes safely online. No technical background needed. Every command is written out for you to copy.

  • Windows and Mac
  • Free to start

    Start here

    The words, in plain English

    Five words do most of the work in this guide. Read these once and the rest makes sense. Nothing here is as complicated as it sounds.

    On your computer

    Git

    A free program that keeps a history of your work. Think of it as a very good undo button that never forgets.

    On the internet

    GitHub

    A website that stores a copy of your project online. It is the safe backup, and the place other people can see your work.

    Your assistant

    Claude

    The AI you already chat with at claude.ai. It can read your project and suggest changes.

    Your assistant, hands on

    Claude Code

    A version of Claude that runs on your own computer and can actually open, write and save your files.

    Jargon

    Repository (repo)

    Just a project folder that Git is watching. When someone says repo, picture a folder.

    Jargon

    Commit and push

    Commit saves a snapshot on your computer. Push sends those snapshots up to GitHub.

    One picture to hold on to

    Git is the filing cabinet in your office. GitHub is the copy kept in a fireproof vault across town. Claude is the assistant who does the filing for you. You are setting up all three to talk to each other.

    About “PC” and “Windows”

    They mean the same thing here. If your computer is not an Apple Mac, use the Windows / PC setting in the switch at the top of this page. The steps on screen change to match your computer.

    Choose one

    People often talk about “connecting Claude to GitHub” as if it were one thing. It is really three, and they do different jobs. Read the three cards, pick the one that matches what you want, and skip the rest.

    Path A · 5 minutes

    Claude reads my code

    You stay in your browser at claude.ai. Claude can look at your files and answer questions about them. It cannot change anything.

    Works on the free plan. Nothing to install.

    Go to Path A

    Path B · 10 minutes

    Claude writes code online

    Claude works on a computer in the cloud, makes the changes, then offers them back to you on GitHub for approval.

    Needs a paid plan. Still nothing to install.

    Go to Path B

    Path C · 30 minutes

    Claude works on my computer

    The full setup. Git and Claude Code live on your machine. Claude opens your files, changes them and saves them to GitHub.

    Needs a paid plan. This is the real thing.

    Go to Path C
    Not sure which

    Do Path A first. It takes five minutes, it is free, and nothing on your computer changes. Once you have seen Claude read your code, you will know whether you want Path B or Path C.

    Before you start Path B or Path C

    Claude Code needs a paid Claude plan: Pro, Max, Team, Enterprise, or an Anthropic Console account with credits. The free claude.ai plan does not include it. Path A works on every plan, including free.

    Path A · In your browser · Free

    Let Claude read your code

    This is the GitHub integration, sometimes called the GitHub connector. You give Claude permission to look inside your GitHub projects, then you chat to it normally. It is read only, so nothing you have can be changed or broken.

    What Claude sees, and what it does not

    Claude reads file names and file contents on the branch you pick. It does not read your commit history, your pull requests, or your issues. It cannot save, push, or delete anything.

    01

    Sign in to Claude

    Any computer · 1 minute

    Open your browser and go to claude.ai. Sign in, or create a free account if you do not have one yet.

    02

    Open the add menu in a chat

    In claude.ai · 1 minute

    Start a new chat. In the lower left corner of the message box, click the + button.

    Then choose Add from GitHub.

    If you are using a Project instead

    Projects have their own version of this. Open your project, find the project knowledge panel, click the + in its upper right corner, then choose GitHub.

    03

    Sign in to GitHub and choose your repos

    In your browser · 2 minutes

    The first time you do this, Claude sends you to GitHub to log in. GitHub then asks which projects Claude is allowed to see. You get two choices:

    • All repositories. Claude can see every project on your account.
    • Only select repositories. You tick the specific ones. Safer, and easy to change later.

    Pick Only select repositories and tick the one you want to work on. You can always add more later.

    Back in Claude, a file browser appears. Tick the files or folders you want Claude to read, then confirm.

    04

    Ask Claude something about your code

    In claude.ai · 1 minute

    Type a normal question and send it. Try one of these to check it worked:

    • “Explain what this project does, in plain English.”
    • “Where is the sign-in code, and what does it do.”
    • “What would you improve first in this project.”

    If Claude answers with details that are actually from your files, the connection is working.

    Your files do not update on their own

    Claude keeps a snapshot from the moment you connected. When you change your code, click the Sync icon, or Sync now, so Claude sees the newest version.

    Path B · In your browser · Paid plan

    Let Claude write code online

    This is Claude Code on the web. Claude borrows a computer in the cloud, opens your project, makes the changes you asked for, and then offers them back to you on GitHub. You still install nothing. You review every change before it counts.

    01

    Make sure you have a repo on GitHub

    On github.com · 3 minutes

    Claude needs an existing project to work on. If you do not have one yet, make an empty one now.

    1. Go to github.com/new.
    2. Type a name in Repository name. Letters, numbers, dots, dashes and underscores only.
    3. Choose Private unless you want the world to read it. Both are free.
    4. Tick Add a README file. This matters. It stops the project being completely empty, which makes everything afterwards easier.
    5. Click Create repository.
    No GitHub account yet

    Go to github.com, click Sign up, and follow the prompts. You must verify your email address before GitHub lets you create a repository.

    02

    Open Claude Code on the web

    In your browser · 2 minutes

    Go to claude.ai/code and sign in with your Claude account.

    Claude asks to connect to GitHub. Follow the prompt. GitHub installs something called the Claude GitHub App and asks which projects it can reach. Choose Only select repositories and pick the one you just made.

    03

    Create your working environment

    In your browser · 2 minutes

    Claude shows a short form. You can accept the defaults on every field.

    • Name. Anything you will recognise.
    • Network access. Leave it on Trusted.
    • Environment variables and Setup script. Leave both empty for now.

    Click Create environment.

    04

    Give Claude a job, then check its work

    In your browser · 5 minutes

    Below the message box there is a repository selector. Click it and choose your project and its branch.

    Next to it is a mode setting. It starts on Accept edits, which lets Claude get on with it. If you would rather see the plan before anything changes, switch it to Plan.

    Now ask for something small, for example:

    Type this into Claude 
    Add a short description of this project to the README file.

    When Claude finishes, you will see a change indicator such as +42 -18. Click it to read exactly what changed. If you are happy, click Create PR at the top of that view.

    What is a PR

    PR is short for pull request. It is GitHub’s way of saying “here are some proposed changes, have a look before we make them official.” Nothing is final until you merge it.

    Two things people trip on

    Closing the browser tab does not stop Claude. The job keeps running.

    A cloud session can reach any project the connected GitHub account can see, not only the ones you ticked. If that matters to you, limit access on GitHub’s side rather than relying on the tick boxes here.

    Path C · On your computer · Paid plan

    The full setup on your machine

    Seven steps. Take them in order and do not skip any. The switch at the top of this page decides whether you see the Windows steps or the Mac steps, so check it says the right thing before you begin.

    Do not want a terminal at all

    There is a Claude Code desktop app with buttons instead of typed commands. If the black text window puts you off, install that instead and use its Code tab. You still need steps 01 to 03 below so that Git and GitHub are ready.

    01

    Create your GitHub account

    On github.com · 5 minutes

    1. Go to github.com and click Sign up.
    2. Follow the prompts. Your username is public, so pick one you are happy for other people to see.
    3. Verify your email address when GitHub asks. You cannot create a repository until you do.
    Turn on two-factor sign-in while you are here

    It is not compulsory for a brand-new account, but GitHub does make it compulsory once you start doing certain things, and it gives you only 45 days’ notice. Setting it up now with an authenticator app takes two minutes and saves a locked-out afternoon later.

    02

    Install Git

    On your computer · 10 minutes

    Windows
    1. Go to git-scm.com/downloads/win. The download usually starts on its own.
    2. Open the downloaded file. If Windows asks whether to allow changes, click Yes.
    3. The installer shows a lot of screens. Change nothing. Click Next on every screen, then Install, then Finish.

    The defaults matter here. They include a helper called Git Credential Manager, which is what lets you sign in to GitHub with a normal browser window instead of fiddling with tokens.

    Now open Git Bash: click Start, type Git Bash, press Enter. A text window opens. Type this and press Enter:

    Git Bash 
    git --version

    You should see something like git version 2.51.0.windows.1. Any version number means it worked.

    Mac
    1. Press Command and Space together, type Terminal, press Enter.
    2. A text window opens. Type the command below and press Enter.
    Terminal 
    git --version

    One of two things happens:

    • You see a version number such as git version 2.39.5. Git is already there. Move on.
    • A box appears offering to install the command line developer tools. Click Install, agree to the terms, and wait. It can take fifteen minutes. When it finishes, run git --version again to confirm.

    Macs also need a helper so GitHub sign-in happens in a browser window rather than at the keyboard. If you already use Homebrew, install it with the two commands below. If you do not know what Homebrew is, skip this and carry on. You can come back if step 06 asks you for a password.

    Terminal · optional 
    brew install git
brew install --cask git-credential-manager
    03

    Tell Git who you are

    Once, on this computer · 2 minutes

    Git writes your name against every change you save, so it needs to know it. Type these two commands one at a time, pressing Enter after each. Replace the name and email with your own and keep the quotation marks.

    Windows: Git Bash · Mac: Terminal 
    git config --global user.name "Your Name"
git config --global user.email "you@example.com"

    Use the same email address as your GitHub account. That is what links your saved work to your GitHub profile.

    To check it stuck, type:

    Check 
    git config --global user.name

    It should print your name back at you.

    04

    Install Claude Code

    On your computer · 5 minutes

    Windows

    You need PowerShell for this, not Git Bash and not the old black Command Prompt. Press Windows key and X together, then choose Terminal or Windows PowerShell.

    How to tell you are in the right window

    PowerShell starts its line with PS, like PS C:\Users\YourName>. If there is no PS, you are in Command Prompt. Close it and open Terminal instead.

    PowerShell 
    irm https://claude.ai/install.ps1 | iex

    You do not need administrator rights. When it finishes, close the window and open a new one, then check it worked:

    New PowerShell window 
    claude --version
    Pick one method and stay with it

    There are other ways to install Claude Code on Windows. Mixing them can leave you with two copies that update separately and behave differently. Use the command above and nothing else.

    Mac

    In Terminal, paste this and press Enter:

    Terminal 
    curl -fsSL https://claude.ai/install.sh | bash

    When it finishes, close the Terminal window and open a new one, then check it worked:

    New Terminal window 
    claude --version

    A version number such as 2.1.211 (Claude Code) means you are set. Your Mac needs macOS 13 or newer.

    If something looks wrong later

    There is a built-in check-up command. It only looks, it never changes anything:

    Health check 
    claude doctor
    05

    Log in to Claude Code

    First run · 2 minutes

    Type this and press Enter:

    Windows: PowerShell · Mac: Terminal 
    claude

    Your web browser opens by itself. Sign in with your Claude account, the same one you use at claude.ai. The terminal then prints Login successful and asks you to press Enter.

    If the browser does not open

    Press the c key. That copies the sign-in link so you can paste it into a browser yourself. If the web page shows you a code instead of sending you back, paste that code into the terminal where it asks.

    A paid plan is required here

    Claude Code needs Pro, Max, Team, Enterprise, or an Anthropic Console account with credits. If you are on the free plan, this is where it stops. Path A above still works on free.

    06

    Bring your project down from GitHub

    On your computer · 5 minutes

    This is the step that actually joins Git, GitHub and your computer together.

    1. On github.com, open your project.
    2. Click the green Code button above the file list.
    3. Make sure the HTTPS tab is showing, then click the copy icon next to the web address.

    Back in your terminal, move to where you want the project to live:

    Choose a home for it 
    cd Documents

    Now type git clone, a space, then paste the address you copied. To paste: Command and V on a Mac, or right-click in Git Bash on Windows.

    Replace with your own address 
    git clone https://github.com/your-username/your-project.git

    Git makes a new folder named after the project, inside wherever you currently are. Step into it:

    Use your own project name 
    cd your-project
    The sign-in box that appears the first time

    On your first clone or push, Git asks you to sign in. A browser window opens. Sign in to GitHub and approve it. Your computer remembers, so this happens once.

    Your normal GitHub password will not work here. GitHub stopped accepting passwords for this years ago. Always use the browser sign-in.

    07

    Start Claude inside your project

    The payoff · 5 minutes

    You are in the project folder. Now start Claude there so it can see everything:

    Inside your project folder 
    claude

    Ask it something real. Try:

    Type this into Claude 
    Add a short description of this project to the README file, then save it to GitHub.

    Claude reads your files, shows you what it wants to change, and asks permission before it touches anything. Say yes and it makes the change, saves it with Git, and sends it up to GitHub. Refresh your project page on github.com and you will see it there.

    Four things to know about the Claude window
    • You cannot click things. Use the arrow keys.
    • Esc stops Claude mid-job.
    • Type /help to see what it can do.
    • Type exit to leave.
    Windows only, and optional

    Claude Code runs commands through Git Bash if it finds it. You installed Git in step 02, so it will. If you had skipped Git, Claude would use PowerShell instead. Either works.

    Worth knowing

    Staying in control

    None of this hands over the keys. A few habits keep it that way.

    Permission

    Claude asks first

    Claude Code shows you what it wants to change and waits for a yes before it edits a file or runs a command. Read what it is proposing rather than approving on autopilot.

    Secrets

    Never paste passwords

    Do not put passwords, API keys or card details into a chat. If a file in your project holds a secret, keep that file out of Git using a .gitignore file.

    Access

    Share the least you can

    When GitHub asks which projects Claude can reach, choose Only select repositories. You can widen it later in seconds. Narrowing it after a mistake is harder.

    Review

    Read before you merge

    A pull request is a proposal, not a done deal. Open the changed files and read them. If anything looks wrong, close the pull request. Nothing is lost.

    Recovery

    Git is your undo

    Every change you commit can be undone. That is the whole point of Git. Commit early and often and you always have a way back.

    Privacy

    Private stays private

    A private repo is visible only to you and people you invite. Connecting Claude does not make it public. Public repos are readable by anyone, so keep personal details out of them.

    If it goes wrong

    Common problems, plain fixes

    Every one of these has happened to everybody. None of them mean you have broken anything.

    “git” or “claude” is not recognised

    The program installed, but your terminal window was already open and has not noticed. Close the window completely and open a new one, then try again. This fixes it nine times out of ten.

    If it still fails on Windows after installing Claude Code, run this in PowerShell, then open a fresh window:

    PowerShell 
    $currentPath = [Environment]::GetEnvironmentVariable('PATH', 'User')
[Environment]::SetEnvironmentVariable('PATH', "$currentPath;$env:USERPROFILE\.local\bin", 'User')
    “irm is not recognized” when installing Claude Code

    You are in Command Prompt, not PowerShell. Close it. Press Windows key and X, choose Terminal or Windows PowerShell, and run the command again.

    The reverse also happens. If you see The token ‘&&’ is not a valid statement separator, you are in PowerShell but running the Command Prompt version. Use the PowerShell command instead.

    Authentication failed, or GitHub keeps rejecting my password

    Your GitHub password does not work for this. It has not worked since 2021. When the sign-in box appears, use the browser sign-in option instead.

    If your computer saved a wrong sign-in earlier, clear it out and try again:

    • Windows: Control Panel, then User Accounts, then Credential Manager. Find the GitHub entry and delete it.
    • Mac: open Keychain Access, search for github, and delete the entry.

    Then run your command again and sign in through the browser.

    “fatal: not a git repository”

    You are standing in the wrong folder. Git only works inside a project folder it is tracking. Move into your project first:

    Use your own project name 
    cd your-project
    “fatal: remote origin already exists”

    Your project is already pointed at a GitHub address, and you are trying to add a second one. Look at what is there, then point it where you actually want:

    Check, then correct 
    git remote -v
git remote set-url origin https://github.com/your-username/your-project.git
    Claude cannot see my private or work repository

    Usually a permissions gate rather than a fault. Go to github.com/settings/applications, open the Claude entry, and look under Organization access.

    • If there is a Grant button next to your organisation, click it.
    • If it says Request, an administrator at your workplace has to approve it.

    Disconnecting and reconnecting GitHub inside Claude will not fix this. It has to be done on GitHub.

    Claude is answering about an old version of my code

    In Path A, Claude holds a snapshot from when you connected. It does not refresh by itself. Click the Sync icon, or Sync now, to pull the current version.

    I typed something and nothing happened

    Usually normal. Many Git commands succeed in silence. To see where things stand:

    Ask Git what is going on 
    git status
    I closed the window. Have I lost my work

    No. Anything you committed is on your computer. Anything you pushed is also on GitHub. Closing a terminal window does not delete files.

    In Path B, closing the browser tab does not even stop Claude. The job keeps running and you can come back to it.

    From here on

    The handful you actually use

    There is no need to learn Git properly. Five commands cover almost everything, and Claude will run most of them for you if you ask.

    Everyday Git commands and what each one does
    CommandWhat it does
    git pullFetches the newest version from GitHub. Run it before you start work.
    git statusShows which files you have changed. Harmless. Run it whenever you are unsure.
    git add .Selects all your changed files, ready to be saved.
    git commit -m "what I changed"Saves a snapshot on your computer, with a short note.
    git pushSends your saved snapshots up to GitHub.

    A normal session is: pull, do your work, add, commit, push. That is the whole rhythm.

    The shortcut

    Inside Claude Code you can skip all of that and simply say: “save my changes and push them to GitHub.” Claude runs the commands and shows you what it did.

    Where to go next

    Two ideas are worth learning after this. Branches let you try something risky on a copy, so the working version stays safe. Pull requests are how changes get reviewed before they become official. GitHub’s own free guides at docs.github.com/en/get-started cover both well.
